# 环境库与场景编辑器

> 当前可见列表有 8 个环境；2026-10-24 加入西湖三岛水域、加冷盆地、瓦尔港，默认各有 12 艘无人艇，详见 [集群实景场景](usv-sites.md)。下面的六个通用预设保留 API 兼容；其程序化地形、默认双载具和桥梁净空说明仅针对这些基础预设。

基础环境库包含六个可重复生成的水域场景，可与现有 18 款载具组合使用。点击页面顶部的“环境库”进入。基础环境、设施、植被和水面均由代码生成，不请求地图、贴图或外部模型。新增的「算法库」可使用当前可见的 8 个环境，并将实验时刻的艇群带入此编辑器，见 [算法库说明](algorithms.md)。

新增第七个独立的 `deepwater` 深水港示范，详见 [深水港组件说明](marine.md)。它使用本地打包的 CC0 摄影 HDRI；此页以下的默认范围与 120 m 飞行高度描述针对原六个基础场景，深水港为 2400 × 1800 m、飞行高度 0–160 m。

## 环境预设与单位

| variant | 名称 | 范围（X × Z，米） | 默认种子 | 主要内容 |
| --- | --- | --- | --- | --- |
| `lake` | 开阔湖面 | 500 × 500 | 2101 | 湖岸、缓坡、林地、码头、观测站 |
| `river` | 曲折河道 | 600 × 400 | 2102 | 连续弯道、收窄河段、两岸植被及监测设施 |
| `harbor` | 港池码头 | 500 × 400 | 2103 | 港池入口、防波堤、货运栈桥、仓库和集装箱 |
| `islands` | 岛礁水域 | 800 × 600 | 2104 | 四个岛屿、露出水面的礁石、岛间水道 |
| `bridge` | 跨河桥区 | 600 × 400 | 2105 | 桥面、独立桥墩、引桥、桥侧护栏 |
| `waterfront` | 城市滨水 | 600 × 500 | 2106 | 建筑、滨水步道、阶梯岸线、停靠平台 |

坐标单位为米，Y 向上，+Z 为载具前向。水位固定为 Y=0；飞行边界为场景水平范围内的 Y=0–120。无人机与无人艇保持原模型尺度，不随场景大小放大。地形、设施尺寸均为原创演示设定。

每个环境提供 12 个无人机出生点和 12 个无人艇出生点。初始配置在首个相应出生点放置一架轻型巡检无人机和一艘轻型巡检无人艇；无人机根节点高度为 10 m，无人艇根节点高度为 0 m。

## 编辑和保存

- 环境选择与当前编辑状态分离；环境分别保留本次页面会话的草稿，来回切换可恢复载具及视角。模型工作台的当前款式和设置也保留。窄屏初始折叠左侧目录，点击「环境与载具」可展开。
- 从左侧下拉列表选择型号并添加，可重复添加同一型号。优先使用通过检查的未占用出生点，无空位时仍允许添加并显示重叠提示。
- 点击模型、屏幕标签或左侧载具列表选择对象。双击标签或点击“聚焦所选”查看细节。未选择对象时隐藏位置与配色编辑项，并禁用聚焦操作。
- “平移”提供世界坐标轴拖拽；“朝向”仅开放 Y 轴旋转。右侧数值输入可精确编辑位置和偏航角。无人艇 Y 锁定为 0。
- `yaw` 在配置文件中以弧度保存；界面显示角度。正值遵循 Three.js 的 Y 轴旋转约定。
- 配色即时更新，其他载具保持独立；“移除所选载具”只移除当前实例。
- 底部「视角」菜单统一提供全景、正上方俯视、鸟瞰、贴水与场景细节，具体名称随场景变化；旧版六个基础环境只显示适用的全景和俯视。聚焦后可拖动和缩放进一步查看。视口聚焦后，`Home` 返回全景，`F` 聚焦所选。「保存图片」导出画面，「专注视图」收起侧栏并扩展场景，再次点击恢复编辑。
- 图层开关控制载具标签、水域轮廓、静态障碍包围体和出生点。波纹与桨叶动画分别控制；降低动态效果偏好启用时，水面动画默认关闭。
- 原六个程序化基础环境可修改种子并重建，保留载具位置并重新检查；现有 8 个展示场景使用固定工程或公开地理布局，隐藏种子重建按钮。
- 出界、离开水域或碰撞会显示警告，仍允许编辑和导出。刷新页面不会自动持久化草稿，请用“导出 JSON”保存。
- 导入先校验并创建替换资源，成功后才替换当前场景。错误文件不会清空当前编辑。
- “保存图片”下载当前三维画面的 PNG，不包含面板或 HTML 标签。

## 独立构造接口

`src/environments/` 只依赖 Three.js，不需要 DOM、载具模块或 Vite。可将整个目录复制到其他 TypeScript 项目。

```ts
import { createEnvironment, checkPlacement, surfaceObstacles } from './environments';

const environment = createEnvironment({ variant: 'bridge', seed: 2105 });
scene.add(environment.root);

// 使用方应用 presentation 建议，负责相机、灯光及渲染。
camera.position.set(...environment.presentation.cameraPosition);
camera.lookAt(...environment.presentation.target);

// 每帧调用；暂停时不调用。只改变水面视觉时间。
environment.update(deltaSeconds);

const issues = checkPlacement(environment.spatial, {
  id: 'boat-1',
  kind: 'usv',
  position: [0, 0, 0],
  yaw: 0,
  bounds: { min: [-0.4, -0.3, -1], max: [0.4, 1.2, 1] },
});

const waterCrossingSolids = surfaceObstacles(environment.spatial);
environment.dispose();
```

完整示例见 `examples/environment.ts`：同时构造桥区、一架无人机及一艘无人艇，并提供更新、检查结果与释放方法，已纳入单元测试。`src/scenes/config.ts` 中的 `conservativeBounds` 应在模型根节点平移、旋转前调用；其无人机范围包含完整桨盘扫掠空间。

返回值：

| 字段 | 用途 |
| --- | --- |
| `root: THREE.Group` | 环境几何，原点与空间数据一致 |
| `spatial: SpatialData` | 纯数据，可序列化，供仿真与位置检查使用 |
| `presentation` | 建议背景、雾距离、太阳位置、相机位置与目标；不自动修改使用方 Scene |
| `update(dt)` | `dt` 为非负有限秒数，只推进视觉水面时间 |
| `dispose()` | 幂等释放本实例资源并从父节点移除 |

种子必须是 0–4294967295 的整数。相同版本的代码、款式和种子生成相同空间数据。环境实例不共享需释放的资源；一个实例释放不会影响另一个。实例内部设施细节、树木使用共享几何或 InstancedMesh。

## 空间数据与检查含义

```ts
type Point2 = [x: number, z: number];
type Point3 = [x: number, y: number, z: number];
interface Polygon { outer: Point2[]; holes: Point2[][] }
```

- `bounds`：水平场景范围，包含 `minX/maxX/minZ/maxZ`。
- `water`：水域多边形，表达岸线及岛礁孔洞。要得到完整可通行条件，须同时排除 `surfaceObstacles(spatial)` 返回的跨水位实体；部分码头与岸线相接，不强行转为不合法的相交孔洞。
- `obstacles`：稳定 ID、名称、类别、XZ 轮廓与孔洞、`minY/maxY`。渲染与检查使用相同定义。树木以包含树冠和树干的保守棱柱记录；缓坡用最高点范围保守检查。
- `flight`：无人机整体包围范围所需满足的高度上下界。
- `spawnPoints`：ID、载具类别、世界位置及偏航角。
- `waterLevel` 固定为 0，视觉波纹不会改变该值。

`checkPlacement(spatial, placement, others?)` 返回问题数组，代码包括 `bounds`（越界）、`altitude`（飞行高度）、`water`（水域或水位）、`obstacle`（静态障碍）和 `vehicle`（载具重叠）。问题带中文说明，碰撞项附带对方 ID。

检查使用模型局部保守包围盒，将其按偏航角转为世界平面轮廓，再与多边形和垂直区间比较。岸线接触按不安全处理。它不进行三角网格精确碰撞，也不模拟流体、地形穿行、动力学或规划算法。

桥区的桥面位于 Y=16–19 m，桥墩分别位于 Z=−43、+43 m，跨越水位。位于 X=0、Z=0 的船可以从桥下通过；同水平位置的无人机在桥面高度与桥面碰撞，在足够高的位置则可通过。桥面不会被误投影为堵死整个河道的水面障碍。

## JSON 配置 V1

配置记录环境款式与种子、载具实例 ID、型号、世界位置、偏航角、缩放、三种颜色，以及所选载具、相机、图层和动画状态；不保存几何、纹理或 Three.js 对象。载具型号格式为 `quadrotor-inspection`、`usv-endurance` 等，与模型库一致。

`parseSceneConfig(text)` 校验并返回结构化配置；`serializeSceneConfig(config)` 校验后输出 JSON。合法的越界或碰撞姿态不会因位置提示被拒绝。

为保证导入可用，V1 的结构限制为：文件最多 2 MB、载具最多 100 个；ID 为不超过 64 个字母、数字、下划线或短横线且不能重复；位置和朝向须为绝对值不超过 1,000,000 的有限数，缩放为 `(0,100]`，颜色采用 `#RRGGBB`；无人艇 Y 必须为 0；相机位置不能与目标完全重合。未知版本、环境或型号，以及缺失/类型错误字段均拒绝。新添加载具缩放固定为 1。

## 验证与性能记录

```sh
npm test                  # 模型、环境、位置检查与配置测试
npm run build             # 类型检查与生产构建
npm run dev               # 先启动开发服务器
npm run test:environments  # 另一个终端运行，使用本机 Edge
npm run test:browser       # 原模型工作台回归验收
```

环境验收输出位于 `artifacts/environments/`，包括六场景全景、俯视、载具近景、桥区障碍显示、窄屏截图和往返配置样例。`acceptance.json` 记录浏览器错误、绘制调用、重复切换后的 GPU 资源数量，以及 12 个真实尺寸载具的帧间隔测量。

性能数据来自本机无头 Edge、1440×1000 的 CSS 视口；它不是其他设备上的帧率承诺。第一版以 12 个载具验证，100 是配置保护上限，不代表已完成百载具性能优化。环境与模型工作台分开渲染，隐藏的工作台暂停帧更新。
